### 0.3 The anti-hallucination toolkit this research suggests

1. Names drift between releases and old names are hidden, not removed. Examples found: `ShellFeatures.CreateShellDefinition` (2024, 2025) became `ShellFeatures.CreateDefinition` (2026+); `FlangeFeatures.CreateFlangeDefinition` (2024) became `CreateDefinition` (2025+); `HoleFeatures.AddDrilledByDistanceExtent` (2024) became `AddDrilledByDistanceExtent2` (2025+); dimension retrieval moved from `GeneralDimensions.Retrieve` (2024) to `Sheet.RetrieveAnnotations` (2025) to `Sheet.RetrieveAnnotations2` (2026.1). Hidden members usually stay callable through COM, but they disappear from the docs and from IntelliSense. `[V:doc]` H25/WhatsNew.htm, H26/WhatsNew.htm; `[V:interop]` MT.
2. The type library on the user's machine is the ground truth for that machine. An MCP should read it at startup (`pythoncom.LoadRegTypeLib` in Python, reflection over the interop DLL in .NET) and build its own enum table and member index, instead of shipping hardcoded constants. One community MCP already does exactly this to qualify each new release `[V:code]` (cenitu/inventor-mcp-server field notes).
3. Existing community MCPs contain errors that look plausible: one sets STL `ExportUnits=4` believing it means millimetres (the docs say 4 = centimetres, 5 = millimetres), another calls `Application.FileLocations.TemplatesPath`, a member that does not exist in any interop from 2024 to 2027 (the real one is `Application.FileOptions.TemplatesPath`), and a widely copied community iLogic rule exports DXF through the STEP translator GUID. Treat community code as evidence that a call shape works, never as a spec.

## 1. Connection and hosting models

### 1.1 Attaching to or starting Inventor (all external hosts)

- ProgID is `"Inventor.Application"`. Attach: VB `GetObject(, "Inventor.Application")`, C# `Marshal.GetActiveObject("Inventor.Application")`, C++ `CLSIDFromProgID` + `GetActiveObject`. Start: `CreateObject("Inventor.Application")`, C# `Activator.CreateInstance(Type.GetTypeFromProgID("Inventor.Application"))`, C++ `CoCreateInstance(..., CLSCTX_LOCAL_SERVER, ...)`. A started instance is invisible until `Application.Visible = True`. `[V:adn]` Ekins "Inventor API Fundamentals 004 - Connecting to the API" (2008, reposted at blog.autodesk.io).
- There is only the version-independent ProgID; on a machine with several Inventor versions, the one registered last answers. To target a version, start that version's `Inventor.exe` yourself and attach. `[V:code]` dariusnaicker/inventor-ai `docs/api_notes.md` (community claim; consistent with Ekins using only the one ProgID).
- `Marshal.GetActiveObject` exists only in .NET Framework 1.1-4.8.1; it is absent from .NET Core/.NET 5+. A .NET 8/10 external EXE must P/Invoke `oleaut32!GetActiveObject` (or use `Microsoft.VisualBasic.Interaction.GetObject`). `[V:src]` https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.marshal.getactiveobject (applies-to list stops at netframework-4.8.1).
- Several Inventor processes: all register under the same ROT moniker and `GetActiveObject` returns the first one registered; a second, hand-started Inventor cannot be reached that way. `DispatchEx` always starts a new process. `[V:code]` cenitu field notes (empirical, Inventor 2026/2027).
- An `Inventor.exe` started by automation keeps running after the client exits; releasing references and waiting after `Quit()` avoids a windowless orphan process. `[V:code]` cenitu field notes.
- `Application.Ready` (Boolean) says whether initialization, including start-up add-ins, is finished; use with `ApplicationEvents.OnReady`. `[V:doc]` H26/Application_Ready.htm. Content Center access raises `E_FAIL` until `Ready` is True `[V:code]` cenitu.

### 1.2 Out-of-process COM from Python with pywin32 (`win32com`)

Functions that exist in pywin32 (`win32com/client/__init__.py`): `Dispatch`, `DispatchEx`, `GetActiveObject(Class, clsctx)`, `GetObject`, `CastTo(ob, target, typelib=None)`, `DispatchWithEvents`, and the `constants` container. `gencache.EnsureDispatch` builds the makepy (early-bound) wrapper. `[V:src]` https://github.com/mhammond/pywin32/blob/main/com/win32com/client/__init__.py

Behaviour confirmed in the pywin32 source:
- `CastTo(ob, "PartDocument")` calls `gencache.EnsureDispatch` itself when the object is not makepy-wrapped and raises `ValueError("Must be a makepy-able object for this to work")` otherwise. So any use of `CastTo` silently switches that process to early binding and writes a `gen_py` cache. `[V:src]`
- `win32com.client.constants` is an empty container that is filled from makepy-generated modules; with pure dynamic dispatch, `constants.kPartDocumentObject` raises `AttributeError`. `[V:src]` (class `Constants` with a list of dicts filled by generated modules)
- `pythoncom` does not expose `CoRegisterMessageFilter` (the string does not occur in `com/win32com/src/PythonCOM.cpp`). An `IMessageFilter` in Python needs ctypes or comtypes. `[V:src]` (absence check of the source file)

Inventor-specific gotchas from people who drive Inventor through pywin32 (all `[V:code]`, community field notes, mostly cenitu/inventor-mcp-server "Inventor 2026/2027 COM API - Field Notes", 2026):
- After `gencache.EnsureDispatch("Inventor.Application")`, plain `GetActiveObject` in other scripts can fail with `KeyError: '_dispobj_'` until `%LOCALAPPDATA%\Temp\gen_py` is deleted. One project disables wrapping globally with `win32com.client.gencache.GetClassForCLSID = lambda clsid: None` so every object stays late-bound with type info.
- Under early binding, `Documents.Open`/`ActiveDocument` return the generic `Document` interface, which has no `ComponentDefinition`; you must `CastTo(doc, "PartDocument")`, and sheet-metal code must `CastTo(cd.Features, "SheetMetalFeatures")` and `CastTo(cd, "SheetMetalComponentDefinition")`. Under dynamic dispatch these casts are not needed. (`CastTo(app.ActiveDocument, "PartDocument")` also appears in toptea/ebom and rapidcad/rapidcadpy.)
- ByRef/out parameters come back as return values or tuples under dynamic dispatch: `occ.CreateGeometryProxy(geom)` returns the proxy; `MeasureTools.GetMinimumDistance(a, b)` returns a tuple whose first item is the distance in cm; `CurveEvaluator.GetParamExtents()` returns `(min, max)`.
- `NameValueMap.Value(name)` is a parameterized property: late-bound pywin32 can read it but cannot set it. Use `NameValueMap.Add(name, value)` (which exists `[V:interop]` MT: `void Add(string Name, object Value)`), or invoke the property-put DISPID.
- Some array arguments (e.g. `CustomTables.Add`) must be passed with explicit `InvokeTypes` and `VT_ARRAY|VT_BSTR`; Python lists are rejected with `E_INVALIDARG`.
- Enum values are best read from the type library at runtime (`pythoncom.LoadRegTypeLib` and walk `TKIND_ENUM`) instead of from `constants`.
- Call `pythoncom.CoInitialize()` on every thread that touches COM, and keep all Inventor calls on one thread. `[U]` (standard COM apartment rule; also stated in dariusnaicker/inventor-ai notes)

Type library file: `RxInventor.tlb` in the Inventor `Bin` folder (Excel VBA references it) `[V:adn]` blog.autodesk.io/inventor-2025-migration-to-net8 (Takehiro Kato, 2024-05-20).

Minimal attach-and-model snippet (composed from verified signatures; enum integers from the official enum pages; not executed):

```python
import win32com.client as w32

app = w32.GetActiveObject("Inventor.Application")          # attach to the running Inventor
kPartDocumentObject, kJoinOperation, kPositiveExtentDirection = 12290, 20481, 20993

tmpl = app.FileManager.GetTemplateFile(kPartDocumentObject)  # optional args omitted
doc = app.Documents.Add(kPartDocumentObject, tmpl, True)
doc.Activate()                                               # community: Add does not always activate
cd = doc.ComponentDefinition
tg = app.TransientGeometry

sk = cd.Sketches.Add(cd.WorkPlanes.Item(3))                  # Item(3) = XY origin plane
sk.SketchLines.AddAsTwoPointRectangle(tg.CreatePoint2d(0, 0), tg.CreatePoint2d(5, 3))   # cm
prof = sk.Profiles.AddForSolid()
ext = cd.Features.ExtrudeFeatures
ed = ext.CreateExtrudeDefinition(prof, kJoinOperation)
ed.SetDistanceExtent("20 mm", kPositiveExtentDirection)     # string with units creates a parameter
feat = ext.Add(ed)
```

Whether the first solid feature must use `kNewBodyOperation` instead of `kJoinOperation` is `[U]`: Autodesk's "Create and Edit an Extrude Feature with a pocket" sample uses join (`[V:doc]` H23/PartFeature_SetEndOfPart_Sample.htm per search extract), one community script says it uses NewBody for the first feature.

### 1.4 pythonnet / .NET interop from Python

- pythonnet 3 loads .NET Framework (`netfx`) by default on Windows; CoreCLR is chosen with `pythonnet.load("coreclr", runtime_config=...)` or `PYTHONNET_RUNTIME=coreclr`, before `import clr`. Assemblies must be loaded explicitly with `clr.AddReference`. `[V:src]` https://pythonnet.github.io/pythonnet/python.html
- The interop assembly for external programs is `Bin\Public Assemblies\Autodesk.Inventor.interop.dll` under the Inventor install; Autodesk recommends Embed Interop Types = No, Copy Local = Yes. `[V:adn]` blog.autodesk.io/inventor-2025-migration-to-net8
- External programs that only use COM generally need no .NET 8 migration, but an external EXE that uses iLogic through `iLogicVb.Automation` must be upgraded to .NET 8 for Inventor 2025. `[V:adn]` same post. A third-party vendor reports that `RunRule`/`RunExternalRule` from PowerShell (a .NET Framework host) fail with Inventor 2025+ and uses `RunRuleDirect` as a workaround `[V:2nd]` support.coolorange.com/kb/ilogic-in-powershell-does-not-work-with-inventor-2025.
- No public pythonnet + Inventor example was found. `[U]` Benefit over pywin32: typed interop, real enums (`Inventor.DocumentTypeEnum.kPartDocumentObject`), `out` parameters handled by the marshaller. Risk: a second runtime in the Python process; interop version must match the installed Inventor.

**Marshalling calls from a server thread to Inventor's main thread.** Inventor has no equivalent of Revit's `ExternalEvent`, and `SynchronizationContext.Current` may be null inside the add-in. ipt-mcp creates a hidden message-only WinForms `Control` in `Activate` (which runs on Inventor's STA thread), forces its handle, runs the TCP/named-pipe listener on a background thread that never touches the API, and posts each request with `Control.BeginInvoke`; `Deactivate` disposes the transport and dispatcher, nulls the cached `Application` and calls `GC.Collect()` to release COM references. `[V:code]` https://github.com/bimwright/ipt-mcp/blob/master/ARCHITECTURE.md ("STA marshalling").

Composed sketch of that pattern (not executed):

```csharp
public class McpAddInServer : Inventor.ApplicationAddInServer
{
    Inventor.Application _app;
    System.Windows.Forms.Control _sta;           // created on Inventor's main (STA) thread

    public void Activate(Inventor.ApplicationAddInSite site, bool firstTime)
    {
        _app = site.Application;
        _sta = new System.Windows.Forms.Control();
        _ = _sta.Handle;                         // force handle creation on this thread
        StartPipeListenerOnBackgroundThread();   // never touches _app
    }

    Task<T> OnInventorThread<T>(Func<Inventor.Application, T> work)
    {
        var tcs = new TaskCompletionSource<T>();
        _sta.BeginInvoke(new Action(() => {
            try { tcs.SetResult(work(_app)); } catch (Exception e) { tcs.SetException(e); }
        }));
        return tcs.Task;                          // caller awaits with its own timeout
    }

    public void Deactivate() { StopListener(); _sta.Dispose(); _app = null; GC.Collect(); GC.WaitForPendingFinalizers(); }
    public void ExecuteCommand(int commandID) { }
    public object Automation => null;
}
```

Transport choice: ipt-mcp uses loopback TCP for the net48 shells (2022-2024) and a named pipe for 2025-2027 "to avoid the loopback-firewall prompt", with a per-session random auth token, and a discovery file per running Inventor at `%LOCALAPPDATA%\Bimwright\ipt-mcp\inventor-<year>-<pid>.json` `[V:code]`.

### 1.7 Performance: in-process versus out-of-process (the numbers)

From "Improving Your Program's Performance" (blog.autodesk.io, 2015-09-01, byline Adam Nagy, signed "-Brian", i.e. Brian Ekins) `[V:adn]` https://blog.autodesk.io/improving-your-programs-performance/:
- 100,000 calls to one property: **74.8 s out-of-process, 0.24 s in-process (about 312x)**; the author warns this measures call overhead only and does not represent typical use, because real calls spend most of their time doing work inside Inventor.
- Out-of-process with `UserInteractionDisabled`: 61.32 s. Caching the Application object: 18.8 s.
- 500 occurrences: 5.32 s unconstrained vs 699 s constrained; constrained with `AssemblyOptions.DeferUpdate` about 54 s, plus `ScreenUpdating` off 49 s, inside a global transaction about 40 s.
- 500 sketch lines: 18.5 s; with `Sketch.DeferUpdates` 1.6 s; with a global transaction 1 s.
- Mechanism: "Inventor is servicing the out-of-process calls while it's also servicing the user-interface. It gives priority to the user-interface and then out-of-process API calls slip in when they can. For in-process programs, Inventor dedicates all of its processing to the API calls."

Related evidence:
- Out-of-process loops run several times faster while the mouse moves over the Inventor window (reported 180-190 ms vs 10-15 ms per batch); Ekins attributed it to Inventor's single main thread serving both UI and API calls and recommended `UserInterfaceManager.UserInteractionDisabled = True`. `[V:2nd]` search extract of forums.autodesk.com "Speed increases when moving mouse over inventor window" (forum returned 403 to the fetcher).
- Users reported large out-of-process slowdowns after upgrading 2017 to 2020 (BOM job from 15 min to over 60 min) `[V:2nd]` search extract of forums.autodesk.com "Inventor 2017 > 2020 changes to out of process API call processing".

- Cost: Automation API = 2 Flex tokens (or 2 Cloud Credits) per processing hour; Flex tokens replaced Cloud Credits on 2022-11-07 `[V:adn]` https://aps.autodesk.com/blog/goodbye-cloud-credits-hello-flex-tokens. - Rate limit: 100 calls per minute per app (client ID), HTTP 429 beyond `[V:2nd]` search extract of APS "Design Automation Rate Limit and Quotas".
- MCP relevance: asynchronous, file-in/file-out (upload model, run work item, download results), minutes of latency, no live session, no viewport, pay per hour. Suits batch tools (configure-and-export, convert, drawing generation from a template) and an MCP hosted on Linux or in the cloud; unsuitable for interactive "fillet that edge" loops.

### 1.12 Hosting model comparison

| Criterion | Python pywin32 out-of-process | pythonnet / .NET EXE out-of-process | In-process .NET add-in + local IPC | Apprentice | Design Automation (cloud) |
|---|---|---|---|---|---|
| API coverage | Full COM API (late-bound) | Full, typed | Full, typed; plus UI, events, ribbon | Read-only geometry/structure; RW properties and references | Full API, no UI, no view |
| Per-call overhead | High: cross-process marshalling, calls served only when UI is idle (74.8 s vs 0.24 s per 100k calls) `[V:adn]` | Same as Python | Lowest (in-process) `[V:adn]` | Runs in caller's process `[V:doc]` | Network + job latency (minutes) |
| Robustness to modal dialogs | Call blocks until the dialog is answered `[V:code]` | Same | Same block, but the add-in can detect it and refuse new work (ipt-mcp HOST_BUSY) `[V:code]` | No dialogs | No UI |
| RPC_E_CALL_REJECTED | Yes, needs retry policy; no message filter in pywin32 `[V:src]` | Yes; CoRegisterMessageFilter via P/Invoke `[V:code]` | Not applicable (same apartment) | No | No |
| Version coupling | Low (late binding); enums must be looked up | Interop per version | One build per .NET generation: net48 (<=2024), net8 (2025-26), net10 (2027) `[V:doc]` | Separate installer since 2026 | Engine per year |
| Install footprint | pip + Python | .NET runtime | Files in an add-in folder; Inventor restart to update | Apprentice installer | APS app, Flex tokens |
| Events (OnSave, selection) | Possible with DispatchWithEvents but needs message pumping `[U]` | Possible | Natural | Not applicable | Not applicable |
| Iteration speed for the team | Fastest | Fast | Slow (restart Inventor on rebuild) | Fast | Slow (upload bundles) |
| Licensing | Uses the user's licensed session | Same | Same | Free | Pay per processing hour |

Recommendation for an interactive MCP: an in-process add-in that owns all Inventor calls on the main thread, plus a thin MCP server process (any language) that talks to it over a named pipe. Keep a Python/pywin32 path only for prototyping and read-only probing. Use Apprentice for offline reads and Design Automation for batch jobs. Evidence strength: the performance gap is primary (Ekins); the threading pattern is community-proven (ipt-mcp) but not documented by Autodesk.

## 2. Threading and robustness

| Item | Detail | Tag |
|---|---|---|
| Single main thread | Inventor serves UI and out-of-process API calls on the same thread; API calls "slip in" when the UI is idle | `[V:adn]` performance post |
| `RPC_E_CALL_REJECTED` (0x80010001) / `RPC_E_SERVERCALL_RETRYLATER` (0x8001010A) | Returned to out-of-process callers while Inventor is busy; community Python MCPs map them to "Inventor is busy, retry" and only auto-retry reads | `[V:code]` cenitu `api_common.py`, RobertBarnettProjects/inventor-forge `engine.py` |
| `IMessageFilter` | COM client hook: `RetryRejectedCall` returning 0-99 retries at once, >=100 waits that many ms, -1 cancels | `[V:src]` https://learn.microsoft.com/en-us/windows/win32/api/objidl/nf-objidl-imessagefilter-retryrejectedcall |
| Non-idempotent retry hazard | A busy-retry wrapper that re-runs a whole tool can duplicate writes (analogous PowerPoint MCP bug) | `[V:code]` github.com/ykuwai/ppt-mcp issue #200 |
| Modal dialogs | An API call that makes Inventor show a dialog does not return until someone answers it (e.g. "save dependents?", resolved-reference prompts). | `UserInterfaceManager.UserInteractionDisabled` (Boolean, RW) | "Enable/Disable user interaction." It is on `Application.UserInterfaceManager`, not on `Application`. Always reset it in a finally block | `[V:doc]` H26/UserInterfaceManager_UserInteractionDisabled.htm; `[V:adn]` performance post |
| `Application.ScreenUpdating` (Boolean, RW) | Stops graphics updates during a series of actions | `[V:doc]` H26/Application.htm |
| `AssemblyOptions.DeferUpdate` | `Application.AssemblyOptions.DeferUpdate` (Boolean) | `[V:interop]` |
| `PlanarSketch.DeferUpdates` | Boolean; large speed-up when adding many sketch entities | `[V:interop]`; `[V:adn]` numbers |
| `TransactionManager.StartTransaction(Document, DisplayName) As Transaction` | Groups operations into one undo step | `[V:doc]` H26/TransactionManager_StartTransaction.htm |
| `Transaction.End()` / `Transaction.Abort()` | Both fail if the transaction is not the current one; other members: `CheckPoints`, `ChildTransactions`, `MergeWithPrevious`, `ParentTransaction`, `State`, `SuppressChangeNotifications` | `[V:doc]` H26/Transaction.htm |
| `TransactionManager` members | `StartTransaction`, `StartTransactionForDocumentOpen`, `UndoTransaction`, `RedoTransaction`, `SetCheckPoint`, `GoToCheckPoint`, `ClearAllTransactions`; properties `CurrentTransaction`, `CommittedTransactions`, `UndoneTransactions`, `TransactionEvents` | `[V:doc]` H26/TransactionManager.htm |
| `StartGlobalTransaction` | Hidden method that merges many transactions; must always be ended or aborted | `[V:adn]` performance post (not in docs or MT, i.e. hidden) |
| Abort semantics | Aborting a transaction on an assembly removes occurrences added inside it | `[V:code]` cenitu |
| `Application.Ready` / `ApplicationEvents.OnReady` | Wait for these before first use after launching Inventor | `[V:doc]` |
| Stale references | After undo, close/reopen or feature deletion, cached COM objects raise `RPC_E_DISCONNECTED` (0x80010108); B-Rep references are invalid after any model change | `[V:code]` cenitu; `[V:adn]` Ekins reference-key post |
| Invisible documents | A document opened with `Documents.Open(path, False)` that nothing references can be closed by Inventor later | `[V:code]` cenitu |
| Error text | `Application.ErrorManager` exposes Inventor's error messages after a failed call (community uses it to turn bare `E_INVALIDARG` into "Failed to build a profile from sketch") | `[V:interop]` member exists; usage `[V:code]` |

Recommended MCP behaviour: one worker on Inventor's thread; per-tool transaction with `End` on success and `Abort` on exception; `SilentOperation` on around open/save/close/export and restored after; check for a modal dialog before dispatching; distinguish "not started" (safe to resend) from "started, outcome unknown" (inspect before retrying), as ipt-mcp does.

### 4.11 Bodies, faces, edges and stable references (critical for "fillet that edge")

**Topology access.** `PartComponentDefinition.SurfaceBodies` -> `SurfaceBody.Faces`/`Edges`/`Vertices` -> `Face.Geometry`, `Face.SurfaceType`, `Edge.GeometryType`; `SurfaceBody.RangeBox` `[V:interop]` (SurfaceBodies, Faces, RangeBox). Indices renumber after every feature; any change to the model invalidates live B-Rep references `[V:adn]` Ekins reference-key post; `[V:code]` cenitu.

**Reference keys** (persistent IDs). `[V:doc]` H26/ReferenceKeyManager.htm, H26/ReferenceKeyManager_BindKeyToObject.htm, H26/Face_GetReferenceKey.htm; `[V:adn]` Mod the Machine "Understanding Reference Keys in Inventor" (2015-09-25, Brian Ekins, archived in ADN-DevTech/typepad-migration-dump).

```text
Document.ReferenceKeyManager As ReferenceKeyManager
ReferenceKeyManager.CreateKeyContext() As Long                               [V:interop]
Face.GetReferenceKey(ByRef ReferenceKey() As Byte, [KeyContext As Long = 0])  [V:doc]  (Edge, Vertex, SurfaceBody, occurrences, features... also have GetReferenceKey)
ReferenceKeyManager.KeyToString(ReferenceKey() As Byte) As String             (Base64)
ReferenceKeyManager.StringToKey(String, ByRef ReferenceKey() As Byte)
ReferenceKeyManager.SaveContextToArray(KeyContext, ByRef ContextArray() As Byte)
ReferenceKeyManager.LoadContextFromArray(ContextArray) As Long
ReferenceKeyManager.CanBindKeyToObject(...), ReleaseKeyContext(...)
ReferenceKeyManager.BindKeyToObject(ReferenceKey() As Byte, [KeyContext As Long = 0], [MatchType As Variant (out SolutionNatureEnum)]) As Object
```

Rules from Ekins' post: a key only works with the document it came from; B-Rep entities (SurfaceBody, FaceShell, Face, Edge, EdgeUse, Vertex, EdgeLoop) need a key context, and the context must be saved (`SaveContextToArray`) together with the keys; never compare key bytes, bind both and compare objects; `BindKeyToObject` can return an `ObjectCollection` when the original face was split (first item is the best match); `BindKeyToObject` fails if the entity no longer exists, so check `CanBindKeyToObject`. In C#, initialise the `MatchType` variable before passing it `[V:doc]`. VBA from the post (trimmed):

```vba
Dim refKeyMgr As ReferenceKeyManager: Set refKeyMgr = doc.ReferenceKeyManager
Dim keyContext As Long: keyContext = refKeyMgr.CreateKeyContext
Dim faceRefKey() As Byte: Call selFace.GetReferenceKey(faceRefKey, keyContext)
Dim contextArray() As Byte: Call refKeyMgr.SaveContextToArray(keyContext, contextArray)
strContext = refKeyMgr.KeyToString(contextArray): strFaceKey = refKeyMgr.KeyToString(faceRefKey)
' later
Call refKeyMgr.StringToKey(strContext, contextArray)
refKeyContext = refKeyMgr.LoadContextFromArray(contextArray)
Call refKeyMgr.StringToKey(strFaceKey, faceRefKey)
Set foundFace = refKeyMgr.BindKeyToObject(faceRefKey, refKeyContext)   ' may be an ObjectCollection
```

How the `ByRef Byte()` arguments marshal through pywin32 late binding was not found in any public code `[U]`; do reference-key work in-process (C#) or in iLogic.

**Transient keys.** `Face.TransientKey As Long` and `SurfaceBody.BindTransientKeyToObject(TransientKey)` are cheap IDs that are valid only until the model is modified `[V:adn]` Ekins post; `[V:interop]`.

**Attributes.** `AttributeSets.Add(AttributeSetName, CopyWithOwner = False)`, `AttributeSet.Add(AttributeName, ValueType As ValueTypeEnum, Value)`, `AttributeManager.FindObjects(AttributeSetName = "*", AttributeName = "*", [AttributeValue]) As ObjectCollection` `[V:interop]`. Ekins: attributes are self-contained and searchable but need write access and a save, and do not return both pieces when a face splits `[V:adn]`.

**iLogic entity names (Inventor 2019+ "Assign Name").** Stored as attribute set `iLogicEntityNameSet`, attribute `iLogicEntityName` whose value is the name `[V:2nd]` ImaginIT "Named Entities & Attributes in Inventor 2019". iLogic API: `IiLogicAutomation.GetNamedEntities(Document) As NamedEntities` with `FindEntity(name)` (throws), `TryGetEntity(name)` (Nothing if absent), `SetName(entity, name)` (throws if taken), `GetName(entity)`, `NameExists(name)`, `DeleteName(entity)`, `Entities` `[V:doc]` iLogic API 2021, NamedEntities interface page `7106a72f-bdd7-a2ac-280c-9ba1ad83ccf6.htm`. The 2019 page states only part documents contain named entities `[V:2nd]` search extract.

**MCP design consequence.** Give the LLM a "describe topology" tool that returns faces/edges with geometric descriptors (surface/curve type, normal or axis, centroid or midpoint in mm, radius, area or length, adjacent faces, owning feature) and a stable handle per entity; make the handle a reference-key string bound under a per-document key context that the server keeps (or an iLogic name / attribute when the user wants persistence in the file); re-bind handles after every feature and report "split" (collection) or "lost" results explicitly. Selecting by "the edge nearest point (x,y,z) of type circle" is a robust fallback.

| Design Automation | Same rules run with `ThisServer` in place of `ThisApplication` | `[V:adn]` aps-run-ilogic |
| `CallingFromOutside` flag | Set by one community MCP as a "documented flag for out-of-process callers"; not in the 2021 member list | `[U]` |

**Should the MCP expose "run iLogic/VB/C# code" as a power tool?** Every serious community MCP has an escape hatch (ipt-mcp `send_code` C#, InventorBridge `run_csharp`, Python projects `run_script`/`run_python`) because a fixed tool set never covers the API `[V:code]`. Risks: the code runs with the user's rights inside Inventor (file system, network, registry), `AddRule` both stores and immediately runs code inside the document, rules can attach to events (`RulesOnEventsEnabled`) and keep running for anyone who opens the file later, and the generated code is exactly where hallucinated API names fail. Mitigations used in the field: a separate toolset that is off by default or behind an explicit permission, a host-side kill switch, a transaction around the script with abort on error, a size cap on output, never storing generated rules in the user's document unless asked, and an `api_lookup` tool so the model checks names before writing code `[V:code]` ipt-mcp README "Safety", InventorBridge README.

## 13. Known pitfalls (consolidated)

1. Hidden-but-callable members and renamed methods between releases (Shell, Flange, Contour Flange, Hole `*2`, dimension retrieval, `CreateArc2dByThreePoints`, `BreakOperations.Add`). Build per-version capability detection. `[V:doc]` `[V:interop]`
2. Database units are cm and radians; numbers passed to Variant arguments are cm/rad, strings use their own units or document units. `[V:doc]`
3. Out-of-process calls are served only when Inventor's UI is idle; 100k trivial calls took 74.8 s vs 0.24 s in-process. `[V:adn]`
4. `UserInteractionDisabled` lives on `Application.UserInterfaceManager`; leaving it True locks the user out; always reset in finally. `[V:doc]` `[V:adn]`
5. Modal dialogs block API calls indefinitely; use `SilentOperation` around file operations and detect dialogs (disabled main window) before dispatching. `[V:doc]` `[V:code]`
6. `SilentOperation` does not make a save succeed while a sketch, flat pattern or in-place edit is active; exit edits first. `[V:adn]`
7. `RPC_E_CALL_REJECTED` / `RETRYLATER` out of process; pywin32 has no message-filter API; never blindly retry writes. `[V:src]` `[V:code]`
8. Every B-Rep reference dies after a model change; use reference keys with a saved key context (and handle split results) or attributes/iLogic names. `[V:adn]`
9. Assembly constraints need geometry proxies (`CreateGeometryProxy`) or entities reached through the occurrence. `[V:doc]` `[V:adn]`
10. `ComponentOccurrences.Add` needs a file on disk; save new parts before placing. `[V:code]`
11. `Documents.Add` may not activate the new document; track documents explicitly. `[V:code]`
12. `CastTo`/`EnsureDispatch` silently switch pywin32 to early binding and can poison `gen_py`; early-bound `Document` hides `ComponentDefinition`. `[V:src]` `[V:code]`
13. `win32com.client.constants` is empty without makepy; hardcode enums only from the official enum pages or read them from the type library. `[V:src]`
14. STEP `ApplicationProtocolType` numbering is inconsistent across Autodesk's own pages (3 vs 4 for AP214); check the output header. `[V:doc]`
15. STL defaults to centimetres (`ExportUnits` 4); millimetres is 5. `[V:doc]`
16. Thread/tap designations must match the installed thread table sheet names and designations exactly. `[V:doc]` `[V:code]`
17. `AddDetailView` and `PartsLists.Add` fail unless their sheet is active. `[V:doc]`
18. `GetTemplateFile` can return an empty string; fall back to `FileOptions.TemplatesPath` and fail loudly on unknown templates. `[V:code]`
19. `Save`/`SaveAs` on assemblies can write dirty dependents, including library/Content Center files. `[V:code]`
20. Stale COM objects (`RPC_E_DISCONNECTED`) after undo, close or delete; re-resolve from the document each call. `[V:code]`
21. Invisible documents have no view (no screenshots) and may be closed by Inventor if unreferenced. `[V:code]` `[U]`
22. `Marshal.GetActiveObject` does not exist on .NET 5+; out-of-process .NET 8/10 hosts need a P/Invoke. `[V:src]`
23. iLogic automation from external hosts broke for some .NET Framework callers in 2025+. `[V:adn]` `[V:2nd]`
24. `AddRule` compiles and runs the rule immediately; generated rules persist in the document. `[V:doc]`
25. Interactive commands (`ControlDefinition.Execute` of modelling commands) wait for user input; do not use them as modelling primitives. `[V:doc]` `[U]`
26. Content Center is unavailable until `Application.Ready`; tree walks take minutes. `[V:code]`
27. Several Inventor instances: `GetActiveObject` binds the first one registered. `[V:code]`
28. Locale: decimal commas in expressions and Content Center values. `[V:doc]` `[V:code]`
29. Community MCP code contains confident but wrong API names/values; treat as hints only. (see 0.3)
30. .NET generation per release means one add-in build cannot serve 2024, 2025-26 and 2027; .NET Framework add-ins "may not work" in 2025+. `[V:doc]` `[V:adn]`
